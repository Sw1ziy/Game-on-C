## 1. Что уже решено

- Игра на C с библиотекой ncurses для задания PS4.
- Игровой мир — двумерная карта в терминале.
- Главный герой — летучая мышь.
- Будет 3 уровня.
- На каждом уровне нужно собрать заданное количество предметов, чтобы воспользоваться выходом.
- Пробел меняет направление гравитации: мышь движется к потолку или к полу.
- Достигнув поверхности, мышь останавливается у неё; повторное нажатие пробела меняет направление обратно.

Название пока записано как «Бетфлип». Латинское написание уточним позже.

## 2. Предварительные решения

Следующие пункты предложены для первой версии и могут измениться после подробного описания:

- Перемещение влево и вправо — стрелками или A/D.
- Прыжка и свободного полёта нет: вертикальное движение задаёт гравитация.
- Направление гравитации можно менять и во время движения между поверхностями.
- В начале уровня гравитация направлена вниз.
- Предметы пока обозначаем нейтрально: «предметы». Их вид и название ещё не выбраны.
- Выход открывается, когда `collected >= required_items`.
- После третьего выхода показывается победа.
- R перезапускает текущий уровень, Q завершает игру.
- Если добавим опасности, столкновение с ними перезапускает текущий уровень вместе с предметами.
- Счёт, ограничение времени, жизни, враги и сохранения пока не входят в обязательную часть.

### Как работает «прилипание»

Мышь занимает свободную клетку рядом с полом или потолком, а не клетку стены.
На каждом шаге физики проверяем соседнюю клетку по направлению гравитации:

1. Если клетка свободна — перемещаем мышь на одну строку.
2. Если это стена — оставляем мышь на месте.
3. После смены гравитации проверяем клетку в противоположном направлении.

Отдельный флаг `is_attached` для первой версии не нужен: состояние определяется картой.
Если мышь движется вдоль поверхности и выходит за её край, она снова движется по гравитации.
Если пробел нажат под выступом, ближайшая стена может сразу остановить движение — это нормальное столкновение.

Для первой версии предлагаем постоянную скорость по клеткам без ускорения.
Ускорение можно добавить позже, если оно понадобится для ощущения игры.

## 6. Данные игры

Рабочие названия типов и полей; точные объявления напишем при реализации.

### Gravity

- `GRAVITY_UP = -1` — вверх.
- `GRAVITY_DOWN = 1` — вниз.

В координатах терминала `y` растёт сверху вниз. Следующая строка: `y + gravity`.

### Player

- `x`, `y` — координаты мыши на карте.
- `gravity` — текущее направление гравитации.

### LevelDefinition — исходное описание уровня

- Исходные строки карты.
- `width`, `height` — размеры.
- `required_items` — сколько предметов нужно собрать.

Этот шаблон не меняется во время игры, чтобы из него можно было восстановить уровень.

### Game — изменяемое состояние

- Рабочая копия карты: собранные предметы удаляются только из неё.
- `width`, `height` — размеры текущей карты.
- `player` — состояние мыши.
- `level_index` — текущий уровень: 0, 1 или 2.
- `collected`, `required_items` — прогресс сбора.
- `status` — игра продолжается, победа или выход пользователя.

Для первой версии достаточно массива карты с фиксированным максимальным размером.
Точные пределы выберем после наброска уровней; динамическая память пока не требуется.
Состояние передаём в функции через `Game *`, чтобы не разбрасывать изменяемые данные по глобальным переменным.

### Обозначения карты — предложение

| Символ | Значение |
| --- | --- |
| `#` | Непроходимая стена, пол или потолок |
| Пробел | Свободная клетка |
| `S` | Старт игрока; при загрузке заменяется свободной клеткой |
| `o` | Предмет для сбора |
| `E` | Выход; его цвет зависит от количества предметов |
| `X` | Опасность, если решим её добавить |

Мышь рисуем поверх карты символом `@` или другим выбранным ASCII-символом.
Координаты мыши хранятся отдельно: при движении не стираем содержимое карты под ней.
Закрытый выход для первой версии можно проходить, но перехода уровня он не вызывает.

## 7. Функции и их обязанности

Это план интерфейсов, а не уже реализованный код. Названия можно уточнять по мере разработки.

### Подготовка терминала

```c
void init_terminal(void);
void init_colors(void);
bool terminal_fits(const Game *game);
```

- `init_terminal`: включает ncurses, отключает эхо и курсор, настраивает клавиши без Enter.
- `init_colors`: создаёт цветовые пары, если терминал поддерживает цвета.
- `terminal_fits`: проверяет место для карты, счётчиков и подсказок.
- При маленьком окне показываем просьбу увеличить его и приостанавливаем физику.
- При завершении обязательно вызываем `endwin()`, включая ошибки после запуска ncurses.

### Загрузка и переходы уровней

```c
bool validate_level(const LevelDefinition *level);
bool load_level(Game *game, int level_index);
bool restart_level(Game *game);
void advance_level(Game *game);
```

- `validate_level`: проверяет размеры, одинаковую длину строк, допустимые символы, один старт и один выход.
- Также проверяет, что предметов не меньше `required_items`, а старт не находится в стене.
- `load_level`: копирует исходную карту, извлекает старт и сбрасывает сбор и гравитацию.
- `restart_level`: повторно загружает текущий уровень.
- `advance_level`: загружает следующий уровень или устанавливает состояние победы после третьего.
- Проверка карты не доказывает её проходимость: проходимость проверяем игрой вручную.

### Движение и взаимодействие

```c
bool is_inside_map(const Game *game, int x, int y);
bool is_wall(const Game *game, int x, int y);
bool try_move_player(Game *game, int dx, int dy);
void flip_gravity(Game *game);
void update_gravity(Game *game);
void process_player_cell(Game *game);
bool exit_is_open(const Game *game);
```

- `is_inside_map`: защищает от обращения за границы массива.
- `is_wall`: считает выход за карту непроходимой областью; сначала проверяет границы.
- `try_move_player`: проверяет целевую клетку, перемещает игрока и обрабатывает её содержимое.
- `flip_gravity`: меняет только направление; не телепортирует мышь к поверхности.
- `update_gravity`: пробует сдвинуть игрока на одну клетку по вертикали.
- `process_player_cell`: собирает предмет, проверяет опасность и открытый выход.
- Предмет исчезает с рабочей карты и увеличивает `collected` ровно один раз.
- `exit_is_open`: возвращает результат сравнения `collected >= required_items`.
- После смерти или перехода уровня прекращаем обработку старой карты в текущем обновлении.

### Управление и время

```c
void handle_input(Game *game, int key);
void update_game(Game *game);
```

- `handle_input`: распознаёт движение, пробел, перезапуск и завершение.
- `update_game`: выполняет один запланированный шаг физики.
- Время измеряем монотонными часами; точную вспомогательную функцию выберем под среду сборки.
- Частые нажатия клавиш не должны ускорять гравитацию.
- Ожидание ввода ограничиваем по времени, чтобы игра двигалась без нажатий и не занимала процессор пустым циклом.
- При загрузке уровня или восстановлении размера окна сбрасываем отсчёт шага, чтобы мышь не делала внезапный рывок.

### Отрисовка

```c
void draw_map(const Game *game);
void draw_player(const Game *game);
void draw_hud(const Game *game);
void draw_game(const Game *game);
void draw_victory(void);
```

- `draw_map`: стены, предметы, выход и согласованные дополнительные объекты.
- `draw_player`: мышь в её текущих координатах.
- `draw_hud`: уровень, собрано/нужно, направление гравитации и управление.
- `draw_game`: собирает кадр и обновляет экран.
- `draw_victory`: финальное сообщение после третьего уровня.
- Функции рисования не меняют состояние игры.

### Главная функция

```c
int main(void);
```

Отвечает за подготовку, загрузку первого уровня, игровой цикл и восстановление терминала.
Правила движения и сбора предметов в `main` не размещаем.

## 8. Схема главного цикла

```text
Подготовить терминал и цвета
Проверить и загрузить первый уровень
Запустить отсчёт времени физики

Пока пользователь не вышел:
    Проверить размер терминала
    Если окно мало — показать сообщение и приостановить физику
    Прочитать клавишу с ограниченным ожиданием
    Обработать управление
    Если игра продолжается и настало время шага — обновить физику
    Нарисовать текущее состояние или экран победы

Восстановить терминал через endwin()
```

## 9. Идея трёх уровней

Пока это цели дизайна, а не утверждённые карты.

1. **Обучение.** Понятный пол и потолок, предметы на обоих, безопасная практика смены гравитации.
2. **Маршрут.** Платформы и выступы: нужно выбирать место смены гравитации, чтобы добраться до предметов.
3. **Комбинация.** Более сложный маршрут с уже знакомыми приёмами; опасности добавляем только после согласования.

Количество предметов и размеры каждой карты определим при проектировании.
Не выбираем количество только ради роста чисел: сложность должна зависеть от маршрута.

## 11. Что проверяем вручную

- Мышь движется по гравитации без нажатий и останавливается у стены.
- Пробел работает у поверхности и посреди движения, повторная смена возвращает направление.
- Мышь не проходит сквозь стены по горизонтали и вертикали.
- Частота ввода не меняет скорость физики.
- Предмет собирается при горизонтальном и вертикальном движении, повторно не засчитывается.
- Выход не переводит дальше при недостаточном количестве предметов.
- Точное требуемое количество открывает выход; переход срабатывает один раз.
- Перезапуск восстанавливает карту, предметы, старт и гравитацию.
- Третий уровень заканчивается победой без обращения к несуществующему четвёртому.
- Маленькое окно и изменение его размера не ломают игру.
- После выхода терминал возвращается в нормальное состояние.
- Каждый уровень действительно можно пройти с выбранной механикой.
